# SANDFORGE

브라우저에서 도는 **입자 단위 물리 실험실**. falling-sand 장르를 열·압력·전기·화학이
한 격자 위에서 동시에 도는 실험대로 끌어올리고, 깊이 레이어와 계측 장비를 붙였습니다.

**[바로 열기 →](https://raccoon-mh.github.io/sandforge/)** · 설치 없음 · 링크 하나

```
138가지 물질   ·   8층 깊이   ·   1,036,800칸   ·   MIT
```

## 무엇이 다른가

The Powder Toy 가 열어 둔 길 위에서, 네 가지를 다르게 했습니다.

| | |
| --- | --- |
| **자는 격자** | 정착한 모래 더미는 CPU 를 한 사이클도 쓰지 않습니다. 청크 단위 수면 + 청크 내부 열/행 비트마스크로, 28,800칸짜리 모래 산이 **0.13ms/틱**입니다 |
| **깊이 레이어** | z 를 8층만 둡니다. 액체는 구멍으로 층을 넘고, 열은 감쇠하며 번지고, **전기는 비아(VIA)로만** 넘습니다 — 그래서 다층 회로기판이 성립합니다 |
| **계측** | 온도·압력·전하를 열화상·압력장·회로 오버레이로 봅니다. 격자 위 아무 칸이나 가리키면 그 칸의 K·압력·통전 상태가 나옵니다 |
| **데이터로 정의한 물질** | 원소 하나가 JSON 레코드 하나입니다. 새 물질을 넣는 데 시뮬레이션 코드를 고칠 필요가 없습니다 |

## 실측 성능

Node 24, 단일 스레드, 480×270×8 격자(약 104만 칸) 기준. `node tools/bench.mjs` 로 재현됩니다.

| 장면 | ms/틱 | 활성 청크 |
| --- | --- | --- |
| 빈 격자 | 0.11 | 0 / 1080 |
| 모래 28,800칸 (정착 후) | 0.11 | 0 / 1080 |
| 물 48,000칸 (정착 후) | 0.13 | 1 / 1080 |
| 불난 숲 49,480칸 (반응 + 열) | 4.23 | 67 / 1080 |
| 8층 동시 폭포 (절대 정착 안 함) | **6.61** | 512 / 1080 |
| 용암 + 물 + 폭발 전 층 | **7.17** | 132 / 1080 |
| 720×405×8 폭포 | 6.78 | 512 / 2392 |

16.7ms 예산 안에서 최악 장면이 7ms 대입니다. 렌더는 GPU 가 맡으므로 CPU 예산과 겹치지 않습니다.

> 최적화 전 같은 장면은 0.93 / 3.42 / 8.05 / 43.82 / 10.28 / 9.40 / 12.93ms 였습니다.
> 차이의 대부분은 **"바뀐 것만 깨운다"** 한 가지에서 나옵니다 — 움직이지 않는 셀은
> 자기 청크를 깨우지 않고, 아무도 깨우지 않은 청크는 통째로 건너뜁니다.
> 나머지는 청크 안의 열/행 비트마스크(폭포가 지나는 4열 말고 28열은 건너뛴다)와,
> 압력장이 완전히 잠잠할 때 스텝 자체를 생략하는 것입니다.

**주의**: 이 수치는 "입자 100만 개 60fps" 가 아닙니다. 기획서의 그 목표는 GPU 컴퓨트 셰이더를
전제한 가설이었고, 지금 엔진은 단일 스레드 JS 입니다. 실제로 확인된 것은
**동시에 움직이는 입자 10만 개가 7ms** 이고, 정착한 입자는 100만 개여도 사실상 공짜라는 것입니다.

## 해 볼 것

- **테르밋**: 산화철(녹) + 알루미늄 가루를 섞고 1200K 로 점화. 2400K 를 뱉으며 녹은 철이 남습니다
- **분진 폭발**: 밀가루를 공중에 흩뿌린 뒤 불씨 하나
- **다이오드**: `전지 → 도선 → P형 → N형 → 도선 → 램프`. 순서를 뒤집으면 불이 안 들어옵니다
- **다층 회로**: 1층에 회로를 깔고 `비아`로 3층에 올린 뒤 거기서 잇기 (`Q`/`E` 로 층 이동)
- **열교환기**: 구리관에 물을 흘리고 바깥을 단열재로 감싼 뒤 발열체를 붙이고 `C` 로 열화상 보기
- **원자로**: 우라늄 덩어리 + 중성자 하나. 납으로 감싸면 멈추고, 흑연을 끼우면 더 잘 도는 것을 볼 수 있습니다

## 만들고 돌리기

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ 로 정적 번들

node tools/bench.mjs   # 성능 실측 (위 표를 재현)
node tools/smoke.mjs   # 물리 동작 확인 — 모래·용암·화재·회로·다이오드
```

`main` 에 푸시하면 GitHub Actions 가 GitHub Pages 로 배포합니다 (`.github/workflows/deploy.yml`).
`vite.config.ts` 의 `base` 가 `/sandforge/` 이므로 저장소 이름을 바꾸면 그쪽도 함께 고쳐야 합니다.

## 구조

```
src/engine/       시뮬레이션. 브라우저 API 를 전혀 쓰지 않아 Node 에서 그대로 돌고 테스트됩니다
  types.ts        물질 레코드와 behaviour 비트의 정의
  data/*.ts       138가지 물질. 여기만 고쳐도 새 물질이 들어갑니다
  materials.ts    레코드 → 평탄한 typed array 테이블 + 반응 조회표로 컴파일
  grid.ts         SoA 셀 저장소 + 청크 수면/깨우기
  sim.ts          틱 파이프라인
  pressure.ts     1/4 해상도 압력·속도장
src/render/       WebGL2. 셀 배열을 텍스처로 올리고 셰이더가 색을 정합니다
src/worker/       워커가 격자와 캔버스를 둘 다 소유합니다 (OffscreenCanvas)
src/share/        RLE 저장 포맷 (.sfg)
```

**왜 전부 워커에 있는가**: GitHub Pages 는 `Cross-Origin-Opener-Policy` 헤더를 세울 수 없고,
그것이 없으면 `SharedArrayBuffer` 를 못 씁니다. 그래서 큰 배열이 스레드를 건널 일을 아예
없애고, 워커가 `OffscreenCanvas` 로 직접 그립니다. 메인 스레드는 UI 만 합니다.

## 물질을 추가하려면

`src/engine/data/` 의 해당 카테고리 파일에 레코드 하나를 더합니다.

```ts
{ id: 'THRM', name: '테르밋', cat: 'powder', color: 0x8a7f6a, phase: Phase.Powder,
  density: 3600, slide: 0.22, tK: 0.2,
  burn: 0.6, burnT: 1200, burnInto: 'MIRN', burnHeat: 2400,
  desc: '점화가 어렵지만 붙으면 2400K 를 뱉으며 철을 남긴다.' }
```

존재하지 않는 물질을 가리키면 **로딩 시점에 그 자리에서** 예외가 납니다 —
조용히 빈칸이 되는 대신 오타를 바로 잡아 줍니다.
